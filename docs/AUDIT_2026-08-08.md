## 1.2 Architecture

- **Pattern:** Feature-first Clean Architecture (presentation / application / domain / infrastructure).
- **Qatlamlar:**
  - `presentation/` — Riverpod providerlar + sahifalar (go_router orqali).
  - `application/` — Command/Query (CQRS uslubida), `*Command` / `*Queries` sinflari.
  - `domain/` — Entity, Repository interfeyslari, Value Object, Event.
  - `infrastructure/` — Isar datasource, Isar model (`.g.dart`), repository implementatsiyalari, tashqi xizmatlar (ML, kamera, snapshot).
- **State management:** `flutter_riverpod ^2.6.1` (StateNotifier + FutureProvider + StateProvider).
- **Routing:** `go_router ^14.6.2` — `AppRouter.router` (`lib/core/router/app_router.dart`).
- **DI:** Elon qilinganidek hech qanday DI kutubxonasi yo'q — Riverpod providerlar DI vazifasini bajaradi. `ProviderScope(overrides: [appDatabaseProvider.overrideWithValue(database)])` — `lib/main.dart`.
- **Event bus:** Ichki `EventBus` (`lib/core/event_bus/event_bus.dart`).
- **Baholash:** Arxitektura yaxshi tuzilgan, qatlamlar toza ajratilgan. Katta kamchilik — `lib/core/network/`, `lib/core/services/`, `lib/core/extensions/` kataloglari **bo'sh** (network layer umuman mavjud emas).

**Kalibrlash bo'yicha qat'iy tavsiya:**
- **Threshold'ni shunchaki taxmin qilib almashtirmang.** Avval real kamera ma'lumotlari bilan kalibrlash kerak:
  1. Xuddi shu odamning 20-50 ta probe (turli yorug'lik/burchak) → genuine score taqsimoti.
  2. Turli odamlarning 20-50 ta probe → impostor score taqsimoti.
  3. Threshold = genuine/impostor kesishuvida FAR (false accept rate) va FRR (false reject rate) muvozanati.
  4. Keyin har bir platformada (Android, Windows) alohida — chunki imzolar engine'ga bog'liq (H-01).
- UI'da slider bor (yaxshi), lekin bu kalibrlash o'rnini bosmaydi — faqat sozlash vositasi.
